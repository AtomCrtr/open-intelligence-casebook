# Cycle analytique commun

Chaque casebook part d'une **question décisionnelle**, pas d'une accumulation de données.

## Règle 0 — Decision-first + Evidence-deep

Le produit final fonctionne à deux vitesses :

1. **couche décisionnelle** — réponse exécutive, Key Judgments, confiance, PIR, risques, décisions et incertitudes critiques ;
2. **couche probatoire** — sources, preuves, chronologie, graphes, mécanismes, hypothèses concurrentes, lacunes, recommandations et annexes.

La couche décisionnelle est rédigée en dernier mais placée en premier. Elle ne doit jamais affirmer davantage que la couche probatoire ne peut démontrer.

```text
Question -> besoins de renseignement -> collecte passive -> registre des sources
-> normalisation -> évaluation des preuves -> hypothèses concurrentes
-> chronologie / graphes / mécanismes -> jugement & confiance
-> risques / indicateurs -> recommandations traçables
-> couche décisionnelle -> red team -> publication
```

La chaîne de preuve sépare systématiquement : **ce qui est observé**, **ce qui est rapporté par une source**, **ce qui est corroboré**, **ce qui est inféré**, **ce qui reste une hypothèse** et **ce qui n'est pas démontré**.

Pour les rapports complexes, une distinction rédactionnelle supplémentaire peut être utilisée : **[FACT]**, **[ASSESSMENT]**, **[HYPOTHESIS]**, **[UNKNOWN]**. Elle ne remplace ni l'évaluation de la source ni le niveau de confiance du jugement.

L'objectif n'est pas de produire une certitude artificielle, mais une conclusion proportionnée aux preuves disponibles et directement utile à la décision.
